Architecture: How I Think & Build Systems

Evaluating agent patterns, state management, and protocol trade-offs for production systems.

PATTERN COMPARISON

ReAct vs. ReWOO Architecture Selection

Choosing the right execution paradigm directly determines latency, LLM API costs, and system reliability.

ReAct (Reasoning + Action)
  • Interleaves thought, tool action, and observation step-by-step.
  • Great for unpredictable, open-ended tool discovery.
  • High latency & high token cost due to repeated context re-prompting.
ReWOO (Reasoning W/O Observation)
  • Generates full tool execution DAG upfront, then executes tools in parallel.
  • ~50% lower latency and ~40% reduced token consumption.
  • Ideal for structured, deterministic multi-tool workflows.
SIMULATION ENGINE:
> Initiating ReWOO Plan Phase... > Step 1 [Planner]: Generated DAG: [Tool_A, Tool_B] -> [Synthesizer] > Step 2 [Worker Engine]: Executed Tool_A & Tool_B concurrently (0.4s) > Step 3 [Solver]: Final response assembled. Total time: 0.6s | Tokens: 420
SCALING PARADIGM

Single-Agent vs. Multi-Agent Orchestration

Knowing when to keep execution bound to a single agent vs. decomposing into a LangGraph multi-agent state machine.

Single-Agent Bounds

Optimal when total tools < 5 and the context window can safely hold all system prompts without prompt contamination or tool hallucination.

Multi-Agent LangGraph

Necessary when separating concern domains (e.g. Code Review vs Security Audit). Isolate tool contexts into specialized agent nodes to preserve focus and allow cyclic state recovery.

STANDARDIZATION

Model Context Protocol (MCP) Integration

Why I adopt MCP to standardize how agents interact with external tools and backends.

MCP eliminates custom glue code by establishing a unified client-server interface for LLMs to discover tools, inspect schemas, and query resources securely over standard JSON-RPC.
